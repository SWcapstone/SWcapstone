# SteelVision MLOps 프로젝트 작업 로그 (2026-05-28)

## 1. 실험 브랜치 데이터 및 로직 마이그레이션 (이력)
`experiment/noleak-patchcore-cascade-20260520` 브랜치에서 최신 연구 성과를 분석하고 마이그레이션을 시도하였습니다.
*   **주요 대상**: v1, v2, v3 버전의 모델 가중치, 학습 데이터셋 명부(CSV), 백엔드 코어 업데이트 로직.

## 2. MLOps 파이프라인 점검 및 전략
기존의 고정된 "Round" 기반 시스템에서 유연한 "버전 중심" 시스템으로 전환하기 위한 전략을 수립하였습니다.
1.  **Metadata-First**: 가중치(`.pt`)와 정보(`.json`)를 한 쌍으로 관리.
2.  **Dataset ID 추상화**: 사용자가 정의한 데이터셋 ID를 기반으로 학습 엔진 가동.
3.  **Explicit Deployment**: UI의 배포 버튼과 백엔드의 `Hot-swap` 로직 결합.

## 3. MinIO 저장소 활용 구조 분석
*   **강점**: 다중 버킷 전략, `state.json`을 통한 재해 복구(DR), 로컬-클라우드 자동 동기화.
*   **보완점**: 대용량 모델 로드 지연 최적화, 모델 무결성 검증 강화.

## 4. UI-백엔드 결합 현황
*   **실시간 대시보드**: 스토리지 스캔 결과와 UI 연동.
*   **비동기 학습 모니터링**: BackgroundTasks와 Polling 방식 활용.
*   **핫스왑 배포**: UI 승인 시 메모리 내 모델 즉시 교체.

## 5. 학습 엔진 고도화 설계 (진행 사항)
UI에서 자유롭게 데이터셋을 선택하되, 시스템 안정성을 위해 아키텍처를 표준화하는 방향으로 설계하였습니다.
*   **Standard Architecture**: Gate(MobileNetV3-Small), Heatmap(ResNet18).
*   **Dynamic Dataset**: `dataset_version_id` 기반의 유연한 경로 해결.

## 6. 향후 과제 (Next Steps)
*   **가중치 복구**: 누락된 `.pt` 파일 확보 또는 재학습을 통한 모델 알맹이(Weights) 생성.
*   **MinIO 통합**: 확보된 모델들의 클라우드 업로드 및 UI 최종 검증.
*   **지능형 진단**: 추론 API 내에 vLLM 기반 결함 진단 로직 고도화.
