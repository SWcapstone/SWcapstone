# 2026-05-22 SteelVision 백엔드 시스템 고도화 및 MLOps 통합 완료 보고서

## 1. 개요 (Executive Summary)
본 보고서는 `dev-ui` 브랜치의 최신 프론트엔드 리팩토링에 대응하여, 백엔드 시스템을 단순 시뮬레이션 서버에서 **"실제 데이터 기반의 관리형 MLOps 엔진"**으로 격상시키기 위한 전 과정의 수행 내역을 담고 있습니다. 코드 정밀 정리부터 시작하여 UI 동기화, 실제 학습 루프 구현, 그리고 저장소 중심의 아키텍처 완성까지 총 4단계에 걸친 통합 작업을 완료했습니다.

---

## 2. 수행 단계별 상세 내역

### Phase 1: 코드 베이스 최적화 및 레거시 정리 (Cleanup)
신규 기능 도입 전, 시스템의 복잡도를 낮추고 유지보수 효율성을 극대화하기 위해 수행되었습니다.
*   **미사용 유틸리티 제거:** `data_utils.py` 및 `device_utils.py` 내의 호출되지 않는 함수들(`verify_split`, `compute_dataset_stats` 등)을 삭제하여 코드 비대화를 방지했습니다.
*   **레거시 주석 및 기술 부채 정리:** 모델 로딩 로직(`load`) 하단에 방치되어 가독성을 저해하던 수백 줄의 과거 구현체 주석을 완전히 제거했습니다.
*   **구조적 정합성 확보:** `serve.py` 내의 중복 임포트 구문을 정리하고, 전역 설정 변수들의 위치를 체계화했습니다.

### Phase 2: UI-백엔드 기능 동기화 및 API 확장 (Sync)
리팩토링된 `dev-ui`의 고급 기능들이 실제 데이터와 연동되어 정상 작동하도록 구현했습니다.
*   **동적 진단명(`issueType`) 생성:** 하드코딩이 아닌 모델의 실제 이상 점수(Anomaly Score)를 기반으로 결함의 심각도를 실시간 판별하여 UI에 전달합니다.
*   **상세 히트맵 데이터 전송:** 모델이 연산한 `normalized_score_heatmap` 원본 행렬을 Base64로 인코딩하여 응답에 포함시켰습니다. 이제 UI의 이미지 뷰어에서 실제 결함 분포를 정확히 확인할 수 있습니다.
*   **상태 관리 객체(`state.json`) 고도화:** Deployment(Production/Staging/Canary) 정보와 학습 레시피를 통합하여 UI 상의 모든 관리 메뉴가 백엔드와 1:1로 매칭되도록 했습니다.

### Phase 3: 완전한 MLOps 데이터 루프 구현 (Core Pipeline)
사용자가 UI 내에서 데이터 관리부터 재학습, 배포까지 수행할 수 있는 "실제 로직"을 완성했습니다.
*   **피드백 기반 데이터셋 구체화:** 사용자가 분류한 오탐/미탐 데이터를 수집하여 실제 학습용 CSV로 변환하는 `/mlops/datasets/from-feedback` 엔드포인트를 신규 구현했습니다.
*   **실제 PyTorch 학습 엔진 가동:** `train_engine.py`의 Mock 코드를 삭제하고, 실제 `GateModel.train_model`과 `PatchCoreModel.fit`을 연결하여 진짜 가중치 파일(.pt)이 생성되도록 했습니다.
*   **사용자 정의 명칭 및 설정 반영:** UI에서 입력한 모델/데이터셋 이름과 하이퍼파라미터가 저장소 메타데이터와 `state.json`에 영구적으로 기록됩니다.

### Phase 4: 시스템 안정성 및 보안 강화 (Safety & Recovery)
운영 환경에서의 실수 방지와 데이터 유실 대응을 위한 안전장치를 마련했습니다.
*   **삭제 안전장치(Protection Policy):** 현재 "운영(PRODUCTION)" 중인 모델은 삭제 명령을 내려도 백엔드에서 원천 차단하여 가동 중단 사고를 예방합니다.
*   **물리 저장소 연동 삭제(Cascading Deletion):** UI에서 삭제 시 가중치(.pt)와 메타데이터(.json), 원본 이미지까지 MinIO 및 로컬 저장소에서 동시에 자동 정리됩니다.
*   **재해 복구(Disaster Recovery):** `state.json`이 변경될 때마다 MinIO의 `configs` 버킷에 자동 백업하며, 서버 재시작 시 이를 다운로드하여 로그와 인벤토리를 100% 복구합니다.

## 3. 저장소 아키텍처: MinIO(S3) 중심의 아티팩트 관리

MinIO를 "진실의 원천(Source of Truth)"으로 삼아, 서버 환경에 독립적인 데이터 영속성을 보장합니다.

### A. 버킷(Bucket)별 데이터 분류 체계
| 버킷명 | 역할 | 주요 저장 파일 |
| :--- | :--- | :--- |
| **`models`** | 가중치 및 실험 결과 | `{ID}.pt`, `{ID}.json` (메타데이터 쌍) |
| **`datasets`** | 학습용 데이터 원천 | `{UUID}.png`, `materialized_dataset.csv` |
| **`feedback`** | 작업자 분류 데이터 | 오탐/미탐 원본 이미지 |
| **`configs`** | 시스템 상태 백업 | `state.json` (로그 및 전역 상태) |

### B. MinIO 내부 구조도 (예시)
```text
MinIO (Artifact Registry)
├── models/
│   ├── production_gate_v1.pt         (실제 운영 모델)
│   └── production_gate_v1.json       (모델 성능 및 파라미터 정보)
├── datasets/
│   ├── feedback_training_v1.csv      (피드백으로 생성된 재학습 명부)
│   └── uploads/ [UUID].png           (UI에서 업로드된 원본 데이터)
└── configs/
    └── state.json                    (시스템 전체 상태 백업본)
```

## 4. 최종 기대 효과 및 정량적 가치
*   **관리 효율성:** 저장소에 파일을 넣기만 해도 UI가 자동으로 감지(Discovery)하며, 클릭 한 번으로 모든 과거 버전 복구가 가능합니다.
*   **운영 안정성:** 삭제 보호 정책과 자동 백업을 통해 인적 실수로 인한 데이터 유실과 서비스 중단을 방지합니다.
*   **기술적 신뢰도:** 모든 추론과 학습 결과는 실제 연산 데이터를 기반으로 생성되므로, 대시보드의 성능 지표가 실제 모델의 역량을 100% 대변합니다.

## 5. 향후 계획: 데이터셋 및 모델 마이그레이션 (Next Steps)
현재의 파이프라인 인프라가 완성되었으므로, 기존의 `round` 테스트 데이터를 걷어내고 최신 실험 결과로 전환하는 작업을 진행할 예정입니다.

1.  **레거시 데이터 제거:** `splits/round*` 및 `models/round*` 파일 전량 삭제.
2.  **`noleak` 데이터셋 통합:** 실험 브랜치에서 검증된 데이터 누수 없는(noleak) 분할 CSV를 표준 데이터셋으로 이식.
3.  **최신 모델 가중치 배포:** `MobileNetV3-Small` 기반의 경량화된 고성능 가중치 파일을 `models` 버킷에 등록 및 기본 운영 모델로 설정.
4.  **최종 시스템 검증:** 신규 데이터셋 기반의 재학습 및 추론 정확도를 최종 점검하여 프로젝트를 마무리.
